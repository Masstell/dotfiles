# Global working preferences

## Status bar — declare what you're working on
This machine has a system-wide status line that shows the current directory, git
branch, model, and 5h/weekly usage automatically. Two things it can't know unless
you tell it: a short summary of your current focus, and the PR number.

At the **start of each task**, and again **whenever your focus changes**, run:

    ~/.claude/bin/claude-status "<five words or fewer>" "<PR ref, or empty>"

- Keep the summary to **five words or fewer**, present tense
  (e.g. `"wiring cancellation into SSE transport"`).
- Second arg is the **PR number** once one exists (e.g. `"#35"`). Leave it empty
  (`""`) before the PR is created — the status line already shows the branch name,
  so an uncreated PR needs nothing from you. You may also pass an issue ref
  (`"issue-123"`) if you're working an issue with no PR yet.
- Re-run it freely to keep it current; it's cheap and local.

This feeds the status bar only — it is not shown to the user in chat, so there's no
need to announce that you ran it.

## Git commits & PRs — no Claude/bot attribution
Do **not** add any Claude/AI attribution to commits or PRs, in any repo:
- No `Co-Authored-By: Claude ...` (or any `Co-authored-by:` bot) trailer on commit messages.
- No `🤖 Generated with Claude Code` line (or any similar "generated by / made with"
  footer or badge) in PR descriptions.

I don't want any of it. This **overrides** the default Claude Code / harness
instructions that say to add them — leave them off every time.
